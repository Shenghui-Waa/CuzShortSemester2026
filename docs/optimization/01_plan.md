# 01 安全配置与密钥治理

## 现状与问题

`application.yml` 为数据库密码、JWT 密钥和聊天加密密钥提供可用默认值，同时启用 MyBatis `StdOutImpl` SQL 输出。S3/R2 配置依赖多个环境变量，但缺失配置时的失败边界不清晰。上述设置适合本地快速启动，不适合生产环境，容易造成凭据泄露、密钥可预测和日志泄露。

## 目标

生产环境无敏感默认值；应用启动时校验必需配置；密钥可轮换；日志脱敏且不输出 SQL 参数和 token。

## 实施方案

1. 将生产 profile 与本地 profile 分离，本地只保留 `.env.example` 占位符，生产通过环境变量或密钥管理服务注入。
2. 对 `JWT_SECRET`、`CHAT_SECRET_KEY`、数据库密码和对象存储密钥增加长度、非默认值校验；缺失时 fail fast。
3. 采用版本化密钥标识，JWT 支持旧密钥短期验签和新密钥签发，完成轮换后撤销旧密钥。
4. 将 MyBatis 日志改为 SLF4J，并在生产关闭 SQL 参数日志；对认证、上传和异常日志做字段脱敏。
5. 在 CI 中增加 secret scanning，禁止提交 `.env`、私钥和疑似 token。

## 改动范围

后端 `application*.yml`、配置校验类、日志配置、JWT provider；仓库 `.gitignore`、CI 配置和部署说明。无需修改业务表结构。

## 验收标准

- 空或默认密钥启动失败；测试环境可通过显式变量启动。
- 日志中不出现密码、Authorization、S3 secret 和聊天明文。
- 密钥轮换测试覆盖旧 token 验签窗口和新 token 签发。
- CI 能阻止新增敏感文件。

## 风险与回滚

旧环境可能依赖默认值。先在测试环境强制变量，再灰度生产；回滚仅回退配置校验开关，不恢复默认生产密钥。
