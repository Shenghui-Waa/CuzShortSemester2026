# 05 文件上传与对象存储治理

## 现状与问题

文件上传已有扩展名和大小限制，但对象存储配置缺失时的行为、内容类型验证、文件名隔离、恶意内容处理、删除补偿和访问权限仍需系统化。CDN URL 与 endpoint URL 的返回策略也需要统一。

## 目标

上传资源可验证、可追踪、可撤销；业务记录与对象存储最终一致；公开资源与私有资源访问边界清晰。

## 实施方案

1. 使用 magic number 检测真实 MIME，限制图片像素、SVG 脚本和压缩炸弹；服务端重新编码图片时去除元数据。
2. 使用不可预测对象 key，按用户/业务/日期隔离，禁止使用用户输入拼接路径。
3. 将上传分为预签名直传和后端确认两个阶段，数据库记录 pending/available/deleted 状态。
4. 业务删除、替换和失败上传通过异步补偿任务清理对象；对象存储删除失败进入重试队列。
5. 对私有资源使用短期签名 URL，公开资源配置 CDN 缓存和防盗链；限制单用户频率与总配额。
6. 在启动时校验 storage-support 与必需配置，提供本地开发 mock 存储适配器。

## 改动范围

FileController、FileUtil/S3ClientUtil、配置校验、文件元数据表、前端上传 API 和部署配置。

## 验收标准

- 伪造扩展名、恶意 SVG、超大图片和超配额请求均被拒绝。
- 上传失败不会留下无法追踪的孤儿对象。
- 私有 URL 过期后不可访问，跨用户不可读取。
- R2、OSS 和本地 mock 至少各有一条集成测试。

## 风险与回滚

迁移现有 URL 时保留旧读取兼容；新上传先灰度启用元数据状态，清理任务需支持 dry-run。
