# 10 部署、配置与运行观测

## 现状与问题

项目提供本地启动配置，但环境变量、健康检查、日志格式、指标、备份、迁移和回滚策略未形成完整运行手册。Maven Wrapper 在当前 PowerShell 环境不能启动，前端构建也受本机权限影响，说明环境可重复性仍不足。

## 目标

开发、测试、生产配置边界清晰；发布可观测、可回滚；数据库和对象存储具备恢复方案。

## 实施方案

1. 为 local/test/staging/prod 建立配置模板和差异清单，所有必需变量在启动阶段校验。
2. 增加 Spring Actuator 健康检查、数据库/S3 依赖探针、版本信息和优雅停机配置。
3. 采用结构化 JSON 日志，关联 request id/user id（脱敏），为错误率、延迟、连接数、订单失败和上传失败建立指标。
4. 固化 JDK、Maven、Node、包管理器版本；在 CI 和部署镜像中使用同一工具链。
5. 数据库迁移采用版本化工具或明确脚本顺序，发布前自动备份并验证恢复；记录 schema 版本。
6. 发布采用蓝绿或滚动策略，保留上一版本镜像、配置版本和回滚命令；禁止未经审批直接重启生产服务。

## 改动范围

后端 profile、Actuator/日志配置、容器或部署脚本、CI/CD、数据库迁移和运维文档。无需改变前端业务功能。

## 验收标准

- 新环境按文档可从零启动并通过健康检查。
- 关键请求可按 request id 检索，敏感字段不进入日志。
- 发布失败能在约定时间内回滚到上一版本，数据库备份可恢复。
- 环境版本和构建产物可追溯到提交和配置版本。

## 风险与回滚

Actuator 和指标端点必须限制网络访问；先在 staging 验证探针和优雅停机，再推广生产。迁移脚本不可逆操作必须提供备份和反向脚本。
