# 09 测试体系与持续集成

## 现状与问题

当前后端测试主要覆盖 Spring 上下文、JWT/BCrypt；前端构建本身存在类型错误，Controller、数据库集成、权限矩阵、订单并发、文件上传和 WebSocket 缺少稳定自动化验证。

## 目标

每个核心业务链路都有可重复的单元、集成和端到端保护；合并前能自动发现契约、安全和回归问题。

## 实施方案

1. 后端为 Service 状态机、金额计算、权限判断、加密工具和 DTO 校验补齐单元测试。
2. 使用 Testcontainers 或隔离 MySQL 测试库覆盖 Mapper、事务、行锁、迁移和真实分页 SQL。
3. 用 MockMvc 覆盖公开/用户/管理员 API、越权访问、错误响应和幂等请求。
4. 为 WebSocket 建立握手认证、断线、ack、重复消息和 Origin 测试。
5. 前端增加 router guard、auth store、request interceptor、核心页面和表单校验测试；采用 Playwright 做登录、发布、下单、聊天冒烟。
6. CI 分阶段执行格式检查、静态类型、单测、集成测试、构建、依赖和 secret 扫描，并上传失败产物。

## 改动范围

后端 `src/test`、前端测试配置与测试目录、Docker/Testcontainers 配置、CI workflow 和测试数据。

## 验收标准

- 核心路径覆盖率和关键分支覆盖率有明确门槛。
- 权限矩阵、订单并发和数据库迁移测试在 CI 稳定通过。
- 前后端构建失败会阻止合并；测试失败可定位到具体产物。
- 至少一条真实浏览器端到端流程在隔离环境通过。

## 风险与回滚

集成测试耗时较长，先把快速单测作为必需检查，数据库和浏览器测试并行或按夜间任务运行；不得为追求通过率跳过安全断言。
